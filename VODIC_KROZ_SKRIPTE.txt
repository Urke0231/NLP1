OPSTI PREGLED
--------------------------------------------------------------------------------
Ceo projekat je pipeline za klasifikaciju sentimenta srpskih tekstova (pozitivan
/ negativan / neutralan / mesovit). Skripte se pokrecu OVIM REDOSLEDOM:

  data.py                    -> pomocni modul, ucitava i cisti anotirani skup
  preprocessing.py           -> pomocni modul, sprema varijante teksta
  01_statistika.py           -> deskriptivna statistika + slaganje anotatora
  02_osnovni_modeli.py       -> klasicni (linearni) ML modeli nad TF-IDF i sl.
  03_enkoderski_modeli.py    -> Ollama embeddinzi (zamrznuti) + klasicni klasif.
  03b_encoder_finetuning.py  -> PRAVI fine-tuning BERT-olikih transformera
  04_dekoderski_modeli.py    -> veliki generativni jezicki modeli (LLM), prompt-ing

data.py i preprocessing.py se ne pokrecu direktno (osim testa na dnu) - to su
biblioteke koje 01-04 uvoze (import). Zato ih objasnjavamo prve.

Svaka skripta iz faze 3 (02, 03, 03b, 04) resava ISTI problem (klasifikacija
sentimenta) ali RAZLICITIM pristupom, da bi se pristupi mogli uporediti:
  02  = klasicni "bag of words" pristup (TF-IDF + logisticka regresija/SVM/NB)
  03  = recenicni vektori (embeddinzi) iz gotovog modela + klasicni klasifikator
  03b = pravo fino podesavanje (fine-tuning) transformera
  04  = veliki jezicki model kome se samo zada prompt (bez treniranja)

Zajednicki protokol evaluacije (bitno da se razume pre citanja koda): SVUDA
(osim 04, gde nema treniranja) koristi se K-slojna (obicno 10-slojna)
stratifikovana unakrsna validacija (StratifiedKFold) BEZ odvojenog test skupa.
To znaci da ne postoji "train/test split" u klasicnom smislu - ceo skup podataka
prolazi kroz K rundi, u svakoj rundi 1/K je validacija a ostatak trening, i na
kraju se sve metrike racunaju iz tih K rezultata. Razlog: skup podataka je mali
(rucno anotiran), pa bi izdvajanje posebnog test skupa ostavilo premalo primera
i za trening i za pouzdanu procenu.

   Razlog: anotatori/anotacioni alati mogu koristiti razlicite nazive za istu
   klasu, a sav kasniji kod (sklearn, matplotlib) ocekuje dosledne stringove.

   LABEL_MAP = {
       "positive": "positive", "pozitivan": "positive", "poz": "positive", "+1": "positive",
       "negative": "negative", "negativan": "negative", "neg": "negative", "-1": "negative",
       "neutral": "neutral", "neutralan": "neutral", "neu": "neutral", "0": "neutral",
       "mixed": "mixed", "mesovit": "mixed",

--- CELINA 1: Transliteracija cirilica -> latinica ---

Zasto: SerbianStemmer i vecina gotovih jezickih modela (CLASSLA, BERT-ici)
ocekuju latinicu. Ako bi tekst ostao mesan (cirilica + latinica), isti pojam
("Beograd" / "Београд") bi model video kao dve razlicite reci, sto razvodnjava
statistiku i kvari klasifikator.

_CYR2LAT = {
    "А": "A", "Б": "B", ... "Љ": "Lj", "Њ": "Nj", "Џ": "Dž", ...
}

def cyr_to_lat(text: str) -> str:
    """Prevodi cirilicki tekst u latinicu. Latinicki tekst ostaje nepromenjen."""
    return "".join(_CYR2LAT.get(ch, ch) for ch in text)

Napomena: visestruka slova (lj, nj, dz) se resavaju mapiranjem SVAKOG
cirilickog znaka pojedinacno u odgovarajuci latinicki niz (npr. "Љ" -> "Lj"),
tako da redosled obrade karaktera nije problematican.

def normalize_whitespace(text): return re.sub(r"\s+", " ", text).strip()

def basic_clean(text: str) -> str:
    """Minimalno ciscenje koje se primenjuje na SVE varijante pretprocesiranja."""
    return normalize_whitespace(cyr_to_lat(text))

basic_clean je "baseline" korak koji ulazi u BAS SVE dalje varijante - cak i
"sirovu" verziju teksta (tj. ni "sirovo" nije bas sirovo, vec vec transliterisano
i sredjenih razmaka).

--- CELINA 2: Tokenizacija ---

Zasto regex a ne gotov tokenizator: potreban je jednostavan i brz tokenizator
koji cuva dijakritike (č, ć, š, ž, đ), brojeve i procente (bitno za novinski
domen, npr. "7,9%"), a ne zahteva eksternu zavisnost.

_TOKEN_RE = re.compile(r"\w+(?:[.,]\w+)*%?", re.UNICODE)

def tokenize(text: str) -> List[str]:
    return _TOKEN_RE.findall(text)

Ovo hvata reci, brojeve sa decimalnim zarezom/tackom (npr. "7,9") i opcioni
znak procenta na kraju.

--- CELINA 3: Stemovanje (SerbianStemmer adapter) ---

Sta je stemovanje: grubo odsecanje sufiksa da bi razlicite oblike iste reci
("kuca", "kucama", "kucu") pale na isti (priblizan) koren, sto smanjuje
velicinu recnika i pomaze linearnim modelima kod malih skupova podataka.

Zasto "adapter": SerbianStemmer.py je eksterni fajl (preuzima se sa GitHub-a
autora Nikole Milosevica) i njegov API (naziv funkcije) varira izmedju verzija.
Adapter zato PROBA vise mogucih imena funkcija dok ne nadje onu koja radi:

_STEM_CANDIDATE_NAMES = [
    "stem", "stemWord", "stem_word", "stemmer", "stemming",
    "SerbianStemmer", "stem_text", "stemText","stem_arr","stem_str"
]

def _load_external_stemmer() -> Optional[Callable[[str], str]]:
    sys.path.insert(0, str(Path(__file__).parent))
    try:
        import SerbianStemmer as _ss
    except Exception:
        return None
    for name in _STEM_CANDIDATE_NAMES:
        fn = getattr(_ss, name, None)
        if callable(fn):
            try:
                out = fn("kucama")          # sanity-check poziv
                if isinstance(out, str):
                    return fn
            except Exception:
                continue
    return None

Ako fajl SerbianStemmer.py NIJE prisutan pored ovog modula, koristi se
REZERVNI (fallback) stemer - jednostavno greedy odsecanje najduzeg poznatog
sufiksa sa unapred definisane liste, sortirane po duzini (da se prvo proba
najduzi mogudi sufiks, npr. "ovanje" pre "anje" pre "e"):

_FALLBACK_SUFFIXES = sorted([...], key=len, reverse=True)

def _fallback_stem(word: str) -> str:
    if len(w) <= 3:
        return w                       # kratke reci se ne diraju
    for suf in _FALLBACK_SUFFIXES:
        if w.endswith(suf) and len(w) - len(suf) >= 3:
            return w[: -len(suf)]
    return w

VAZNO upozorenje iz koda: modul EKSPLICITNO belezi da li koristi pravi
SerbianStemmer ili fallback (USING_EXTERNAL_STEMMER), i 02_osnovni_modeli.py
ispisuje upozorenje ako fallback ostane aktivan - jer kvalitet stemovanja
direktno utice na rezultate i to treba pomenuti u izvestaju.

--- CELINA 4: Lematizacija (CLASSLA) ---

Sta je lematizacija (za razliku od stemovanja): vraca STVARNI recnicki oblik
reci (lemu) koristeci pravu morfolosku analizu (npr. "kucama" -> "kuca"), a ne
grubo sečenje sufiksa. Preciznije od stemovanja, ali sporije jer zahteva pravi
NLP model (CLASSLA pipeline za srpski).

_CLASSLA_PIPELINE = None

def _get_classla(use_gpu=False):

    if _CLASSLA_PIPELINE is None:
        import classla                      # lokalni import - modul radi i bez classla ako se ne koristi
        try:
            _CLASSLA_PIPELINE = classla.Pipeline("sr", processors="tokenize,pos,lemma", use_gpu=use_gpu)
        except Exception:

            _CLASSLA_PIPELINE = classla.Pipeline("sr", processors="tokenize,pos,lemma", use_gpu=use_gpu)
    return _CLASSLA_PIPELINE

    ...

Kesiranje na disku (preko md5 hash-a nad sadrzajem teksta) je kljucno: bez
njega bi se svaki put pri ponovnom pokretanju skripte cekala ista spora
lematizacija cele baze. Isti princip (kes u .cache/) koristi se za stemovanje,
NER i Ollama embeddinge u ostalim skriptama.

keep_pos=True dodaje UPOS oznaku uz lemu (npr. "rast_NOUN") - razdvaja
homonime (npr. glagol vs. imenica istog oblika), sto ponekad pomaze linearnim
modelima da bolje razlikuju znacenje.

--- CELINA 4b: Uklanjanje geografskih/politickih imena ---

Zasto ovo uopste postoji: imena drzava/gradova mogu SLUCAJNO korelirati sa
sentimentom u skupu podataka (npr. vesti o domacoj vs. stranoj ekonomiji), a
da sama rec ("Beograd", "Nemacka") nema nikakav sopstveni sentiment. Ako se to
ne ukloni, model moze nauciti laznu (spurious) odliku - npr. da nauci
"Nemacka => negativno" samo zato sto se u datom skupu tako slucajno poklopilo,
a ne zato sto rec "Nemacka" zaista nosi sentiment.

Dve opcije, obe pozivane PRE lowercasing-a/stemovanja/lematizacije:

1) Rucna lista korena (brzo, bez zavisnosti):

GEO_STOPWORD_ROOTS = [
    "srbij", "beograd", "novi sad", "nis", "kragujev",
    "nemack", "berlin", ... "evrop", "amerik", "kin", "rusij", "moskv", ...
]

def strip_geo_stopwords(text: str) -> str:
    kept = [t for t in tokenize(text)
            if not any(t.lower().startswith(r) for r in GEO_STOPWORD_ROOTS)]
    return " ".join(kept)

2) Automatska NER (Named Entity Recognition) detekcija preko CLASSLA - sporije,
ali ne zahteva rucno odrzavanje liste i hvata imena koja lista propusti:

def strip_named_entities_batch(texts, use_gpu=False, entity_types=("LOC","ORG")):
    ...
    for token in sent.tokens:
        tag = token.ner or "O"
        if not any(tag.endswith(f"-{et}") for et in entity_types):
            kept.append(token.text)
    ...

Vazna napomena iz koda: NER MORA da radi na tekstu SA velikim slovima (dakle
PRE lowercasing-a), jer se NER model oslanja na kapitalizaciju da prepozna
vlastita imena.

--- CELINA 5: build_variants() - sastavljanje svih varijanti za poredjenje ---

Ovo je "glavna" funkcija modula - poziva je 02_osnovni_modeli.py da dobije
recnik {naziv_varijante: lista_pretprocesiranih_tekstova}:

def build_variants(raw_texts, include_lemma=True, lemma_use_gpu=False,
                   geo_filter=None) -> Dict[str, List[str]]:
    cleaned = [basic_clean(t) for t in raw_texts]

    if geo_filter == "stopwords":
        cleaned = strip_geo_stopwords_batch(cleaned)
    elif geo_filter == "ner":
        cleaned = strip_named_entities_batch(cleaned, use_gpu=lemma_use_gpu)

    lowered = [t.lower() for t in cleaned]

    variants = {
        "sirovo": cleaned,            # samo translit + whitespace
        "lower": lowered,             # + lowercasing
        "lower+stem": stem_batch(lowered),
    }
    if include_lemma:
        variants["lower+lema"] = lemmatize_batch(lowered, use_gpu=lemma_use_gpu)
    return variants

Redosled operacija je namerno biran: geo-filter ide PRE lowercasing-a (zbog
NER-a), a stemovanje/lematizacija idu POSLE lowercasing-a (stem/lema
algoritmi rade nad malim slovima).

--- CELINA 3: slaganje_anotatora() ---

Racuna medjuanotatorsko slaganje (inter-annotator agreement) na KALIBRACIONOM
skupu - fajlovima gde su VISE anotatora anotirali ISTE tekstove nezavisno.

  common = sorted(set.intersection(*[set(s.index) for s in ann.values()]))

Prvo se nadje presek tekstova koje su SVI anotatori oznacili (da poredjenje
bude korektno - fer je porediti samo one primere koje su svi videli).

  for a, b in itertools.combinations(names, 2):
      k = cohen_kappa_score(ya, yb)

Cohen's kappa se racuna za SVAKI PAR anotatora - ovo je standardna metrika
slaganja koja (za razliku od proste "% slaganja") korigovanjem za slucajno
poklapanje daje realisticniju sliku. Ispisuje se i interpretacija skale
(Landis & Koch): <0.20 slabo ... >0.80 gotovo savrseno.

  try:
      from statsmodels.stats.inter_rater import aggregate_raters, fleiss_kappa
      ...
  except ImportError:
      print("(za Fleiss kappa: pip install statsmodels)")

Fleiss' kappa racuna slaganje za SVE anotatore ODJEDNOM (ne samo parove) - to
je globalna mera konzistentnosti cele grupe. Import je "meko" (try/except) jer
statsmodels nije obavezna zavisnost - ako fali, skripta samo preskoci taj deo
umesto da pukne.

  cm = confusion_matrix([ann[a][t] for t in common], [ann[b][t] for t in common])

Matrica konfuzije izmedju PRVA DVA anotatora pokazuje KOJE se klase najcesce
mesaju (npr. "neutralno" vs "negativno") - to je direktan input za doradu
uputstava za anotiranje (ako se dve klase stalno mesaju, uputstvo za njih
verovatno nije dovoljno jasno).

def _feature_defs() -> Dict[str, callable]:
    return {
        "TF":        lambda: CountVectorizer(token_pattern=TOK, min_df=MIN_DF_REC),
        "IDF":       lambda: TfidfVectorizer(..., binary=True, use_idf=True),
        "TFIDF":     lambda: TfidfVectorizer(..., sublinear_tf=True),
        "TFIDF_1-2": lambda: TfidfVectorizer(..., ngram_range=(1, 2), ...),
        "TFIDF_1-3": lambda: TfidfVectorizer(..., ngram_range=(1, 3), ...),
        "CHAR_3-5":  lambda: TfidfVectorizer(analyzer="char_wb", ngram_range=(3, 5), ...),
        "REC+CHAR":  lambda: FeatureUnion([("rec", TfidfVectorizer(...)),
                                           ("char", TfidfVectorizer(analyzer="char_wb", ...))]),
    }

Objasnjenje razlika:
  - TF: cista frekvencija reci, bez tezinjenja po redkosti
  - IDF: binarno prisustvo x inverse-document-frequency
  - TFIDF: standardni TF-IDF (sublinear_tf=True ublazava efekat vrlo cestih reci)
  - TFIDF_1-2 / 1-3: dodaju bigrame/trigrame (hvataju fraze, npr. "nije dobro")
  - CHAR_3-5: karakterski n-grami - korisni za jezike bogate morfologijom (kao
    srpski), jer hvataju delove reci (koren, sufiks) i bolje se nose sa
    razlicitim oblicima iste reci nego cist "bag of words"
  - REC+CHAR: unija (konkatenacija) recnih i karakterskih odlika u jedan vektor

TOK = r"(?u)\S+" - poseban token_pattern jer je tekst VEC tokenizovan i
razdvojen razmakom (posebno posle stemovanja/lematizacije), pa se koristi
"sve sto nije razmak" umesto podrazumevanog sklearn regexa koji bi drugacije

def evaluate_config(pname, texts, fname, vec_factory, mname, clf, grid, y, n_jobs):
    X = np.asarray(texts, dtype=object)
    cv = StratifiedKFold(n_splits=BROJ_VALIDACIONIH_FOLDOVA, shuffle=True,
                         random_state=SLUCAJNO_SEME)
    pipe = Pipeline([("vec", vec_factory()), ("clf", clone(clf))])

    if grid:
        search = GridSearchCV(pipe, grid, scoring="f1_macro", cv=cv, n_jobs=n_jobs, refit=False)
        search.fit(X, y)
        best = search.best_params_
        idx = search.best_index_
        fold_skorovi = [search.cv_results_[f"split{k}_test_score"][idx] for k in range(BROJ_VALIDACIONIH_FOLDOVA)]
    else:
        fold_skorovi = cross_val_score(pipe, X, y, scoring="f1_macro", cv=cv, n_jobs=n_jobs).tolist()

Kljucna tacka: GridSearchCV se pokrece SA refit=False i fold_skorovi se citaju
IZ NAJBOLJE kombinacije hiperparametara direktno iz cv_results_, umesto da se
naknadno rade dodatne CV runde. Ovo je namerno pojednostavljenje (nije "duboko
ugnjezdena" CV u strogom smislu - hiperparametri se biraju na ISTIM foldovima
na kojima se izvestava skor), sto skripta implicitno priznaje time sto je sve
uporedjivo (isti seed = isti foldovi za sve konfiguracije).

clone(clf) je bitno jer se funkcija poziva IZ VISE NITI paralelno (ThreadPool)
- kloniranje osigurava da dve niti nikad ne dele isti mutabilni estimator
objekat, sto bi izazvalo trke (race conditions).

def _statisticko_poredjenje(rows, outdir: Path):
    """Uparen Wilcoxonov test po foldovima, u odnosu na najbolju konfiguraciju."""
    for r in rows[1:]:
        a, b = np.array(base["fold_skorovi"]), np.array(r["fold_skorovi"])
        p = 1.0 if np.allclose(a, b) else wilcoxon(a, b).pvalue

Zasto uparen (paired) test: buduci da SVE konfiguracije koriste ISTI seed (pa
i iste foldove), moze se direktno uporediti skor konfiguracije A i B NA ISTOM
foldu (par po par) - to je metodoloski jace nego prosto porediti prosecne
skorove, jer eliminise varijansu izmedju foldova kao izvor razlike. Wilcoxon
je neparametarski test (ne pretpostavlja normalnu raspodelu), pogodan za mali
broj foldova (10 parova).

def _http_post(path, payload, timeout=120) -> dict:
    body = json.dumps(payload).encode("utf-8")
    request = urllib.request.Request(f"{OLLAMA_URL}{path}", data=body,
                                     headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(request, timeout=timeout) as response:

def _embed_batch(texts: List[str]) -> List[List[float]]:
    """Vraca embeddinge za jedan paket tekstova uz nekoliko ponovnih pokusaja."""
    for attempt in range(4):
        try:
            output = _http_post("/api/embed", {"model": OLLAMA_MODEL, "input": texts})
            return output["embeddings"]
        except (urllib.error.HTTPError, KeyError):
            break                       # batch endpoint ne postoji -> fallback ispod
        except urllib.error.URLError:
            if attempt == 3:
                raise
            time.sleep(2 ** attempt)    # eksponencijalni backoff

    # Fallback: stariji /api/embeddings endpoint, JEDAN tekst po pozivu
    embeddings = []
    for text in texts:
        ...

Ovo pokazuje "graceful degradation" - prvo se proba brzi batch endpoint
(/api/embed), a ako ne postoji (starija verzija Ollama-e), automatski se
prelazi na sporiji endpoint koji radi tekst-po-tekst. Retry sa eksponencijalnim
cekanjem (2**attempt sekundi) stiti od prolaznih mreznih gresaka.

--- CELINA 2: parse_label() - parsiranje odgovora modela ---

_PARSE = [
    (r"\b(pozitiv\w*|positive|pos)\b", "positive"),
    (r"\b(negativ\w*|negative|neg)\b", "negative"),
    (r"\b(neutral\w*|neutraln\w*|neu)\b", "neutral"),
    (r"\b(mesovit\w*|mixed)\b", "mixed"),
]

def parse_label(raw: str, allowed: List[str]) -> str:
    t = (raw or "").strip().lower()
    for pat, lab in _PARSE:
        if lab in allowed and re.search(pat, t):
            return lab
    return "NEPARSIRANO"

LLM ne vraca uvek CISTO "pozitivan"/"negativan"/"neutralan" - moze dodati
objasnjenje, promeniti oblik reci, ili odgovoriti na drugom jeziku. Regex sa
\w* hvata razlicite oblike (npr. "pozitivno", "pozitivnog"). Ako NISTA ne
odgovara, oznaka je "NEPARSIRANO" - ovo se posebno broji i izvestava (vidi
dole), jer visok procenat neparsiranih odgovora znaci da model ne prati
instrukciju formata, sto je samo po sebi vazan nalaz.
